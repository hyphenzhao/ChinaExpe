# 紫微麦旧存档修复记录

修复日期：2026-10-16（Australia/Sydney）。

## 修复范围与来源

- 检查 `knowledge_base/` 的 1,897 个紫微麦文本存档。
- 修复其中 1,880 个损坏文件；原本正常的 17 个文件不改动。
- 旧文件共含 1,311,972 个 Unicode 替换字符（U+FFFD），这些字符已丢失原始字节，无法可靠地反向转码。
- 按旧 HTML 中的 WordPress 文章 ID，通过紫微麦公开 REST 接口重新获取 UTF-8 标题与正文。遵守原站 robots.txt，分批、限并发获取，并支持失败重试和断点续跑。
- 保留原抓取时间、原链接、当前链接、修复时间和原站更新时间。文章改过永久链接时仍按稳定 ID 匹配。
- 恢复的是修复时原站发布的版本，不宣称与历史快照逐字一致，也没有让 AI 补字或改写。

修复后，全部 1,897 个文本中 U+FFFD 数量为 0，已知乱码模式检测为 0。此检查针对编码损坏，不代表校勘过原作者的文字或命理观点。

## 本地备份与重复执行

```bash
# 只取回并验证前三个损坏文件，不覆盖原件
python scripts/repair_ziwei_archive.py --limit 3

# 修复所有检测到的损坏文件
python scripts/repair_ziwei_archive.py --apply
```

原始 TXT/HTML 备份、原站响应缓存、修复清单及前后 SHA-256 保存在
`data/maintenance/ziwei-encoding/`，均被 Git 忽略。每个原件只备份一次，重试不会覆盖最初备份。
工具拒绝文章 ID 不符、外站链接、受密码保护、过短或仍有乱码的响应。
已经修复的文件会跳过；该工具不是持续同步原站内容的爬虫。

## 索引重建

```bash
# 在 NAS 上运行，使用本地 Ollama bge-m3，不调用付费解读模型
python3 scripts/build_vectors.py --scope all

# 重启应用以加载新向量表和更新后的正文解析器，再重建在线文本索引
curl -fsS -X POST http://127.0.0.1:8765/api/knowledge/build-index
```

紫微麦向量按正文分段（最多 1,200 字符、重叠 100 字符），覆盖全文并保留标题与来源。
嵌入检查点存放在 `data/maintenance/ziwei-vector-cache.sqlite3`，中断可续跑；全部向量成功后才发布新表。
项目的 `data/lancedb/ziwei_knowledge` 会优先于旧的 OpenClaw 共享库使用，旧共享库不修改。
典籍表仍由原有流程生成。文本检索会去除修复元数据，向量检索也会过滤仍损坏的旧片段。

生成索引、向量数据库、备份和 HTML 镜像不上传 GitHub；仓库保存修复后的文本、来源信息、工具与回归测试。
